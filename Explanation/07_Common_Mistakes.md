# 07 · Common Mistakes: NetCostLab

**Rule:** for every module, how to **identify**, **prevent** and **debug** the mistakes it invites. Current to **Phase 5, step S2**; later steps add their mistakes.

---

## Foundation and build mistakes (Phase 4)

| # | Mistake | How you notice it | How to prevent it | How to debug it |
|---|---|---|---|---|
| F1 | **Adding a `Server` target to a launcher-engine project** | UnrealBuildTool stops before compiling anything: "Server targets are not currently supported from this engine distribution." (`UEBuildTarget.cs:1404`) | Check `[InstalledPlatforms]` in `Engine/Config/BaseEngine.ini` before planning around a target type. On a launcher engine, run the editor binary with `-server` instead (`01b` #1, #3) | Probe P2-1 (`09`): the build log line, plus `grep PlatformType BaseEngine.ini` |
| F2 | **Expecting push model to work in a packaged game on the launcher engine** | Nothing fails. `MARK_PROPERTY_DIRTY_FROM_NAME` compiles to nothing, `Net.IsPushModelEnabled` is an unknown command, and the "push" run costs exactly what the polling run costs | Know that `bWithPushModel` defaults to Editor targets only (`TargetRules.cs:1516–1527`). Measure push model in the editor binary, or on a source-built engine with a unique build environment | Type `Net.IsPushModelEnabled` in the console: a packaged game says the command is unknown. The byte check in `Phase2_Raw_Notes/A` shows the cvar string is absent from the game's `NetCore` |
| F3 | **"Fixing" F2 with `bOverrideBuildEnvironment = true`** | It may build, then crash or corrupt memory at run time, because our code and the precompiled engine disagree on push-model structures | Never override a `[RequiresUniqueBuildEnvironment]` setting against precompiled engine binaries (`04` §3) | Crashes inside `NetCore`/`Engine` replication code with no obvious cause; a clean rebuild does not help |
| F4 | **Turning on Iris on the server only** (or only on the clients) | The client is rejected or disconnects at connection time; the logs mention a replication-system mismatch | Pass `-UseIrisReplication=1` (or `=0`) to **every** process of a run. The run scripts build both command lines from one setting | Search both logs for "UseIrisReplication" and "Iris"; `NetDriver.cpp:2725, 2755` is the mismatch check |
| F5 | **Forgetting the Iris plugin** | `-UseIrisReplication=1` is ignored with an ensure: "...is not using Iris because the IrisCore module isn't loaded. Check whether the Iris plugin is enabled." (`UnrealEngine.cpp:14879–14885`) | List `Iris` in the `.uproject` plugins | The ensure text in the log |
| F6 | **Combining Replication Graph with Iris** | `checkf` fires: "ReplicationDriver (...) are not supported with a NetDriver (...) configured to use Iris" (`NetDriver.cpp:7354–7358`): the server stops | Only C3 sets `ReplicationDriverClassName`, and only through the command line, so it can never leak into an Iris run | The assertion text |
| F7 | **A module name used twice** (for example a plugin and the game both called `NetCostLab`) | The second module is silently skipped; its code is missing at run time | Unique names: `NetCostLab` (game) and `NetCostLabCore` (plugin). UnrealBuildTool keys modules by name, case-insensitively (`RulesAssembly.cs:199–206`) | UnrealBuildTool's module list in the build log |
| F8 | **Making every dependency public in `Build.cs`** | Nothing breaks; builds get slower and include paths leak into every dependent module | Public only when a **public header** includes the other module's header; otherwise private (`05` A3) | Look for `Public` dependencies that no file in `Public/` needs |
| F9 | **Launching benchmark processes through `cmd /c start /affinity`** | Every run "passes": `start` returns 0 whatever the program returned | The script pins **itself** (`pin_self`) and then starts the real executable with `Popen`, so the child inherits the mask from its first instruction and its own exit code is visible (`Tools\netlab_env.py`) | Check that the recorded exit code is the game's own, and that the manifest's inherited mask is the intended one |
| F10 | **Starting a packaged game's bootstrap exe** (`Build\Windows\NetCostLab.exe`) instead of the real one | The exit code and process id belong to the bootstrap, not the game | Run `Build\Windows\NetCostLab\Binaries\Win64\NetCostLab.exe` | `tasklist` shows two processes |
| F11 | **Saving `.bat` files with LF line endings** | `cmd.exe` can fail to find `goto` labels | `.gitattributes` keeps `*.bat` as CRLF | `file Tools\*.bat` should say "CRLF" |
| F12 | **Running any Unreal process outside the machine queue** | Another project's benchmark is corrupted, and nobody can tell | Every build, cook, editor run and benchmark goes through `tools\ue_queue.py` | The queue's `history.jsonl` |
| F13 | **Letting an engine plugin write a secret into a committed config file** | After the first editor run, `DefaultEngine.ini` gains an `[/Script/AndroidFileServerEditor.AndroidFileServerRuntimeSettings]` block with a random `SecurityToken` | Disable the default-enabled `AndroidFileServer` plugin in the `.uproject` before the editor first runs (`05` A1); check `git diff Config/` before every commit | `grep -n AndroidFileServer NetCostLab/Config/*.ini` must print nothing (`09`, F-3c) |
| F14 | **Relying on a command-line switch the engine does not parse** (for example `-ExitAfterSeconds`: a search of `Engine/Source/Runtime` in 5.8.4 finds no such string) | The process does not exit; the queue's watchdog kills it | Verify every switch in the source before using it (`06` §5); end runs with `-ExecCmds="quit"` or from the run director | Search the engine source for the switch's `FParse` call |
| F15 | **Switching on Iris without registered sub-object lists** | A handled ensure at start-up on server and clients: "Iris requires replicated actors to use registered subobjectslists…" (`EngineReplicationBridge.cpp:234`), and per-actor warnings that sub-objects "will not replicate properly" | `[SystemSettings] net.SubObjects.DefaultUseSubObjectReplicationList=1` in `DefaultEngine.ini` (`05` A7). Actor code that adds sub-objects must use the registered list (`AddReplicatedSubObject`), not only the virtual `ReplicateSubobjects` | Search the logs for "SubObjectReplicationList"; `09` P2-1d shows the before, F-5 the after |
| F16 | **Ignoring Iris's late-module warning** ("BroadcastLoadedModulesUpdated() called while there are 1 active ReplicationSystems. If polymorphic types are registered we may have corrupt data") | `LogIris: Warning` a frame after the replication system starts | Load modules that register net serializers before the net driver starts. This project registers none. **Checked in S1:** on the server the six late modules are engine tools (`AutomationWorker`, `AutomationController`, `SequenceRecorder`, `SequenceRecorderSections`, `CollisionAnalyzer`, `PerfCounters`: 108 → 114); `NetCostLab` and `NetCostLabCore` load before the replication system exists (`09` S1-f) | `IrisCoreModule.cpp:141–160` is the check; the log line gives the module count; the editor binary's `LogModuleManager: InternalLoadLibrary` lines between the two Iris lines name the modules |

## Workload and replication mistakes (step S1)

| # | Mistake | How you notice it | How to prevent it | How to debug it |
|---|---|---|---|---|
| S1-1 | **Forgetting `Super::GetLifetimeReplicatedProps`** | The actor appears on clients but never moves: `AActor`'s `ReplicatedMovement` is no longer registered | Always call `Super` first (`05` C2) | Client-side position stays at the spawn point; the S1 count check still passes, so S3's arrival log is the real test |
| S1-2 | **Changing a push-based property without `MARK_PROPERTY_DIRTY_FROM_NAME`** | With push on (C2–C6) the change never reaches clients; with push off (C1) it does, so the bug hides in one configuration | Every write goes through a setter that marks the field (`ApplyStateChange`, `ApplyLoadoutChange`, `ApplyToggle`) | `net.PushModelValidateProperties` (`RepLayout.cpp:98–99`, legacy path) checks push-based properties against their real values; S3's staleness log shows changes that never arrive |
| S1-3 | **Spawning the workload on clients as well as the server** | Every client has two copies of every drone: its own (never moving) and the replicated one | Spawn only when `GetNetMode() != NM_Client` (`05` C7) | `-NCLCountLog` shows 512 drones on a client instead of 256 |
| S1-4 | **A random stream whose draw order depends on tick timing** (one stream for everything, or even one per object shared by two kinds of change) | Workload hashes match, but the change sequences differ between runs or configurations: when two changes fall due in one tick in one run and in two ticks in another, they draw in a different order, and every later value differs. Our first S1 version had this (one stream per drone for state *and* loadout, one stream for all props); the S1 review found it | One stream **per event**, seeded from (seed, kind, object, event number) (`MakeStream`, `05` C7); a fixed number of draws per change. Test: `NetCostLab.Workload.ChangeStreamsArePure` | Compare the drones' `Seq`/`Mode` sequences between two runs (S3's server truth log) |
| S1-5 | **Using a possessed pawn as the player's stand-in** | The owning client never receives its own pawn's position (`COND_SimulatedOrPhysics`), and pawn/controller replication is added to every run | A plain actor as the view target (`ANCLPlayerAvatar`, `05` C4) | On a client, the own pawn's position is frozen while others move |
| S1-6 | **Accumulating motion (`Location += Velocity * DeltaTime`)** | Positions drift with frame-time jitter, so the "true" position at an instant cannot be recomputed | Position as a pure function of server time (`LoopPosition`) | Two runs of the same seed disagree on positions at the same server time |
| S1-7 | **Believing the schedule prevents bursts after a hitch** | One frame after a hitch replicates far more changes than normal, and shows up as a spike in the net-tick time | Know what the rule does: at most one change per object per tick (`TakeDue`) stops one object from applying all its missed changes at once, but after a 1 s hitch about 30 ticks' worth of objects are due together (≈ 128 drone changes on the next tick). Our first comment claimed "a hitch never produces a burst"; the S1 review corrected it. Measured runs must be hitch-free: S2 flags frames longer than twice the tick | The server CSV's frame time and `NetCostLab/OutBytes` per frame (S2); test `NetCostLab.Workload.ScheduleKeepsPhase` |
| S1-8 | **Leaving the server's view to the client's camera** | Relevancy and priority depend on what each headless client happens to send; runs are not comparable | Override `GetPlayerViewPoint` on the server (`05` C5) | Log the server-side view position per connection and compare with the avatar |
| S1-9 | **Narrowing an index into a smaller replicated type without a limit** | Drone 32,768 gets index −32,768; player 128 gets slot −128 | Clamp before the cast (`MAX_int16` drones, `MAX_int8` slots) and log an error | `TestEqual` on counts; the `NCL player joined: slot` lines |
| S1-10 | **`TestEqual` with a `uint32`** | A compile error ("ambiguous call"): the overloads are `int32`, `int64` and `SIZE_T` | Compare explicitly with `TestTrue(…, A == B)` (`05` C8) | The compiler message names the overloads |
| S1-11 | **Expecting every client to hold every actor** | A client counts fewer props than the server spawned (733–768 of 768 per S1 sample, in C1 and C4) and the count changes as its avatar moves; it looks like lost actors | Remember that relevancy is part of what is measured: the cull distance (150 m) is shorter than the arena's diagonal (283 m), so far props are correctly not replicated. Check counts against the server's spawn count, and relevancy per client against distance | `-NCLCountLog` on server and clients; a client's count must never exceed the server's, and an actor within 150 m of the avatar must be present (S3's state dump checks this per actor) |
| S1-12 | **Reading the run's settings at begin play** | In a standalone or listen-server world, the host's avatar follows the default seed's loop although `-NCLSeed` was given: the host logs in (`AddPlayer`) before the world begins play (`UnrealEngine.cpp:16646` vs `:16660`). A dedicated server hides the bug, because clients join later | Read settings in the subsystem's `Initialize` (`06` §7) | Log the seed in `AddPlayer`; run standalone with `-NCLSeed=5` |
| S1-13 | **A view that never turns** | Legacy priority treats everything "behind" a fixed +X direction as less important (×0.2 or ×0.4, `ActorReplication.cpp:67–88`), so priorities reflect an arbitrary axis rather than where the player goes. Our first version moved avatars with `SetActorLocation` only | Turn the avatar to its direction of travel each tick (`LoopFacing`, `SetActorLocationAndRotation`) | The server's `GetPlayerViewPoint` rotation per connection; test `LoopMotionMatchesSpeed` checks `LoopFacing` |
| S1-14 | **Splitting a Windows command line with `shlex`** | `shlex.split` (POSIX mode) treats `\` as an escape: `-abslog=D:\Logs\s.log` arrives as `-abslog=D:Logss.log` | Split on whitespace outside double quotes and keep backslashes (`check_job.split_args`) | Print the split list before running |
| S1-15 | **Two quoted arguments with spaces through `cmd /c`** | The step fails in 0.0 s: `'D:\UNREAL' is not recognized as an internal or external command`. With more than two quote characters on the line, `cmd /c` removes the first and the last one, and the path splits at its space. Our first S1 re-check failed exactly so | Pass only one quoted (spaced) argument through `cmd /c`; give further paths relative to a known folder (`run_tests.bat` resolves `LogPath` against `%~dp0`) | The step's own log shows `cmd`'s message; `cmd /?` describes the quote rule |

## Director and measurement mistakes (step S2)

| # | Mistake | How you notice it | How to prevent it | How to debug it |
|---|---|---|---|---|
| S2-1 | **Emitting the start event in the frame that calls `BeginCapture`** | The CSV has no `BenchStart` event: the capture only starts at the next frame (`CsvProfiler.cpp:3870–3895`), and events are dropped while nothing is captured (`:4744–4746`) | Emit it in the first frame that is captured (`SampleFrame`, frame 1) | `csv_stats.py` prints the events it found per file |
| S2-2 | **A byte window and a CSV that cover different frames** | Bytes per second and per-frame timings disagree by a frame at each end | Take the byte baseline at the end of the frame that requested the capture, count exactly the captured frames, and request `EndCapture` in the last counted frame (it is still captured, `:4208–4218`). The S2 check compares the CSV's frame count with the director's | `window_frames` in `_server.json` must equal the CSV's data rows |
| S2-3 | **Sampling connection bytes before the net flush** | Each frame's bytes are the previous frame's; the first and last frames of the window are wrong | Sample at `FWorldDelegates::OnWorldTickEnd`, which runs after `TickFlush` (`LevelTick.cpp:1929` then `:2061`) | Compare the per-frame sum with `OutTotalBytes` deltas over the window |
| S2-4 | **Defining saturation yourself** | Your "saturated" (here: bytes ≥ 90% of rate × frame time) is not the documented metric (`01` §6.4: `IsNetReady() == false`), and it needs its own clamp rules and tests. Our first S2 version did this; the S2 simplify pass replaced it | Read the engine's per-connection count (`GetSaturationAnalytics().GetNumberOfSaturatedFrames()`, tracked at the end of every connection tick, `NetConnection.cpp:5110`) at the window's start and per frame | `saturated_frames` per connection in `_server.json`; `NetCostLab/SatConnections` per frame in the CSV |
| S2-5 | **Quitting before the CSV is on disk** | A missing or truncated CSV, now and then | `EndCapture` returns a future; the server quits only when it is ready | The run script marks the run invalid when the CSV is missing or has the wrong frame count |
| S2-6 | **Hand-built JSON** | A report that Python cannot parse when a path contains a backslash | Write reports with `FJsonObject` and `FJsonSerializer` (`06` §22) | `json.load` in `run_bench.py` raises; the run is invalid |
| S2-7 | **Two `-ini:Engine:` switches assumed to override each other** | Only one of the settings takes effect | The parser walks every `-ini:` token (`ConfigCacheIni.cpp:2341–2345`), so separate switches are fine; each switch's settings are separated by commas | The server log's config dump (`-ExecCmds` with the key) |
| S2-8 | **Capping a client's frame rate with `-dpcvars=t.MaxFPS`** | The log says `Set CVar [[t.MaxFPS:30]]`, yet the client runs at 2,000+ fps (our first S2 run) and sends far more packets than a real client | Know that `UGameEngine::Init` re-applies the user settings and writes `FrameRateLimit` (0) into `t.MaxFPS` on every non-dedicated process (`GameEngine.cpp:1249–1250`, `GameUserSettings.cpp:535–538`). Set the cap after start-up (`GEngine->SetMaxFPS` when the world begins play), and make a run invalid when a client's measured fps exceeds the cap | The client report's `fps`; `run_bench.py` records `client_fps_max` |
